# 批量调色 PRD

## 一、背景

当前修图流程：大图页 → 点「修这张」→ 进 studio → 调参数 → 导出到本地。
问题：**只能一次修一张**。用户想给 50 张都套同一个调色，得一张张手动来。

用户原话：「可以批量导入，一张一张修，也可以多选照片，然后一起调色」。

## 二、核心流程

```
照片列表 → 多选 → 批量调色 → 预览 → 保存
```

### 2.1 多选入口

**入口**：照片列表页（app.js），不是 studio。

当前照片列表是时间线瀑布流，点缩略图进大图查看器。
加一个多选模式：

**触发方式**：
- 长按缩略图 → 进入多选模式，该张默认选中
- 或大图查看器底栏加一个「多选」按钮

**多选模式 UI**：
```
┌─────────────────────────┐
│ 已选 3 张    全选  ✕    │  ← 顶栏变成批量操作栏
├─────────────────────────┤
│ [✓] [✓] [✓] [ ] [ ]    │  ← 缩略图加复选框
│ [ ] [ ] [✓] [ ] [ ]    │
│ ...                     │
├─────────────────────────┤
│    [ ✦ 批量调色 ]        │  ← 底部悬浮按钮
└─────────────────────────┘
```

**交互**：
- 点缩略图 = 选中/取消
- 「全选」= 当前已加载的全部选中
- 「✕」= 退出多选模式
- 底部「批量调色」按钮：只有选了 ≥1 张才可用

### 2.2 批量调色界面

**新建 batch.html**（或复用 studio.html 加参数）。

选 3 张照片后点「批量调色」→ 进入 batch 页面：

```
┌─────────────────────────┐
│ ‹ 批量调色 (3 张)       │
├─────────────────────────┤
│                         │
│      [ 大图预览 ]        │  ← 第一张选中照片
│                         │
│  ◄  1/3  ►              │  ← 切换查看不同照片
│                         │
├─────────────────────────┤
│ 🎛 预设                  │
│ [胶片] [暖调] [冷调] ... │  ← 点一下套预设
│                         │
│ ☀ 调整                   │
│ 曝光  [━━━━●━━━] +0.1  │  ← 拖一下，所有照片实时预览
│ 对比  [━━━●━━━━] +0.05  │
│ 饱和  [━━━━●━━━] +0.08  │
│ 色温  [━━━●━━━━] +0.03  │
│ 锐化  [━●━━━━━━] +0.10  │
│                         │
├─────────────────────────┤
│ [ 应用到 3 张并保存 ]    │  ← 保存按钮
└─────────────────────────┘
```

**交互细节**：
1. 进入时加载第一张选中照片，显示原图
2. 拖滑杆 → 当前照片实时预览（WebGL shader，60fps）
3. 点 ◄ ► → 切换查看其他选中照片的效果
4. 点预设 → 一键套参数，所有照片同步更新
5. 点「应用到 N 张并保存」→ 保存 → 提示「已保存到 3 张照片」

**不做的**：
- 不做 AI 美颜/去物（要调外部 API，有费用、速率限制）
- 不做裁剪/旋转（破坏性操作，不适合批量）
- 不做单独微调（想单独调就回 studio 单张模式）

### 2.3 保存后效果

保存后：
1. 返回照片列表，多选模式自动退出
2. 已调色的照片缩略图上显示「✦」角标
3. 相册里如果引用了这些照片，自动显示调色后的效果
4. 进 studio 编辑某张时，加载已保存的参数（滑块自动定位）

## 三、数据模型

### 3.1 photos 表新增字段

```sql
ALTER TABLE photos ADD COLUMN adjust_json TEXT;
```

存储格式（与 studio.js 的 ADJUSTMENTS 对应）：

```json
{
  "uExposure": 0.1,
  "uContrast": 0.05,
  "uSaturation": 0.08,
  "uTemp": 0.03,
  "uSharpness": 0.1,
  "preset": "复古胶片",
  "updatedAt": "2026-01-10T10:00:00Z"
}
```

### 3.2 API 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| `PUT` | `/api/photos/:key/adjust` | 保存单张调整 |
| `POST` | `/api/photos/batch-adjust` | 批量保存调整 |
| `GET` | `/api/photos/:key` | 返回时带 `adjust` |
| `GET` | `/api/photos?keys=a,b,c` | 批量查询 |

**`POST /api/photos/batch-adjust`**：

```json
// 请求
{
  "keys": ["abc123", "def456", "ghi789"],
  "adjust": { "uExposure": 0.1, "uContrast": 0.05 }
}

// 响应
{ "ok": true, "saved": 3 }
```

## 五、技术要点

### 5.1 WebGL 复用

batch 页面和 studio 共用同一套 shader：

```js
// 从 studio.js 导出 shader 代码
window.StudioShader = {
  frag: '...',  // fragment shader
  vert: '...'   // vertex shader
};
```

batch.js 引入后直接用，不重复写。

### 5.2 性能

- 预览按屏幕尺寸渲染（不是原图分辨率），保证 60fps
- 切换照片只换 texture，不重建 shader
- 保存时只调一次 `POST /api/photos/batch-adjust`（不是 N 次 PUT）

### 5.3 非破坏性

- 调整参数存 JSON，原图不变
- 随时可以重置、改参数
- 相册里随时可以「取消调色」（清空 adjust_json）

## 六、不做的事

1. **不做 AI 批量** — 美颜/去物要调外部 API，有费用、速率限制
2. **不做批量裁剪/旋转** — 破坏性操作，不适合非破坏性模型
3. **不做「复制 A 的调整到 B」** — 第一版只做「多选 → 一次应用」
4. **不做云端渲染** — 服务器不跑 GPU，渲染在浏览器端做
5. **不做修改历史** — 保存就是覆盖，想恢复就回 studio 重置
