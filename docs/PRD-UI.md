## 1. 背景与目标

### 1.1 背景

当前修图页（studio.html）右侧面板存在三个问题：

1. **没有预设系统** — 用户每次修图都从零开始调参数，效率低。像素蛋糕等竞品都有分类预设（婚纱/写真/旅拍/胶片...），一键套用风格。
2. **右侧面板视觉层次弱** — section header 只有文字，没有图标、没有分类标签，用户扫一眼分不清哪个区域是干什么的。
3. **滤镜/模板展示粗糙** — AI 模板只有文字按钮，没有缩略图预览。用户不知道点下去会变成什么样。

### 1.2 目标

> 让修图页的右侧面板从"能用"升级到"好用"：
> - 用户一眼能分清面板结构
> - 常见风格一键套用，不用从零调
> - 点预设/模板之前能看到效果预览

### 1.3 参考：像素蛋糕 UI 模式

从像素蛋糕截图中提取的关键 UI 模式：

| 模式 | 像素蛋糕做法 | 我们的做法 |
|---|---|---|
| Section header | 图标 + 标题 + Free 标签 | 图标 + 标题（不区分付费/免费） |
| 预设分类 | 折叠列表 + 推荐/我的 tab | 分类 tab + 预设卡片网格 |
| 滤镜展示 | 缩略图网格 + 名称 | 缩略图网格（动态生成）+ 名称 |
| 参数滑块 | 内嵌在 section 里 | 保持现有滑块面板，增加预设快捷 |
| 色温/色相 | 独立 section + 滑块 | 整合到色彩 section 里 |

## 2. 用户故事

### US1: 一键套用预设风格

**作为** 婚纱照用户，**我想要** 从预设列表里选一个风格一键套用，**这样** 不用每次从零调 15 个滑块。

验收标准：
- [ ] 预设面板在右侧面板最顶部，默认展开
- [ ] 预设按类别分组（婚纱/写真/旅拍/胶片/黑白/日常）
- [ ] 点分类 tab 过滤预设
- [ ] 点预设卡片一键应用，所有滑块跳到预设值
- [ ] 应用后 toast 提示"已应用「柔光婚纱」"
- [ ] 没打开图片时预设面板不可用（灰色）

### US2: 预设缩略图预览

**作为** 用户，**我想要** 看到预设的视觉效果预览，**这样** 不用盲选。

验收标准：
- [ ] 每个预设卡片显示一个色块渐变预览（代表该预设的色彩风格）
- [ ] 色块基于预设的 hue 字段生成
- [ ] 预览色块在暗色背景下清晰可见
- [ ] 预设名称在色块下方显示

### US3: 右侧面板结构清晰

**作为** 用户，**我想要** 一眼看清右侧面板的结构，**这样** 不用逐个点开看。

验收标准：
- [ ] 每个 section header 有图标 + 标题
- [ ] section header 之间有视觉分隔
- [ ] section 可以折叠/展开
- [ ] 当前选中的 section 有视觉高亮

### US4: AI 模板缩略图预览

**作为** 用户，**我想要** 看到 AI 模板的效果图，**这样** 知道点下去会变成什么样。

验收标准：
- [ ] AI 模板从文字按钮升级为缩略图卡片
- [ ] 缩略图显示模板效果预览
- [ ] 缩略图网格支持横向滚动
- [ ] 点缩略图应用模板

### 3.2 右侧面板视觉升级

#### 3.2.1 Section Header 规格

```
┌─────────────────────────────────┐
│ ▸ 🎨 预设                [收起] │  ← 图标 + 标题 + 操作按钮
├─────────────────────────────────┤
│   [内容区域]                     │
```

- 高度：36px
- padding：0 12px
- 图标：14px，灰色（var(--sink2)）

#### 3.2.2 图标方案

使用 Unicode 字符或 SVG，不引入外部图标库：

| Section | 图标 | 字符 |
|---|---|---|
| 预设 | 🎨 | 调色板 |
| 常规修图 | ⚙️ | 齿轮 |
| AI 修图 | ✨ | 星星 |
| 选区/蒙版 | ◐ | 半圆 |
| 裁剪 | ✂️ | 剪刀 |
| 旋转 | ↻ | 旋转箭头 |

```css

--spanel2:  #26262a;  /* 卡片/按钮背景（不变） */
```

### 3.4 交互规格

#### 3.4.1 预设应用流程

1. 用户点击预设卡片
2. 重置所有滑块值为默认值
3. 应用预设值到 values 对象
4. 重建滑块（buildSliders）
5. 重绘画布（draw）
6. 显示 toast："已应用「柔光婚纱」"
7. 高亮已应用的预设卡片

#### 3.4.2 预设与滑块的联动

- 应用预设后，用户继续调滑块，预设高亮取消
- 用户手动调滑块时，预设不再高亮
- 用户点"重置"后，所有预设取消高亮

#### 3.4.3 Section 折叠

- 点 section header 切换展开/收起
- 收起时隐藏内容区域，保留 header
- 展开状态记住（用 sessionStorage 或 localStorage）
- 默认状态：预设展开，其他收起

### 3.5 边界情况

#### 3.5.1 没打开图片时

- 预设面板显示但不可用（灰色）
- 点预设卡片无反应
- 分类 tab 可切换但无效果

#### 3.5.2 预设数量少时

- 如果某个分类只有 1-2 个预设，卡片网格仍然正常显示
- 不显示空分类（分类 tab 只显示有预设的分类）

#### 3.5.3 窄屏适配

- 预设卡片网格在窄屏时变为 1 列
- 分类 tab 横向滚动
- 模板缩略图横向滚动

## 4. 设计决策

### 4.1 为什么用色块而不是真实预览图？

**决策**：使用 CSS 渐变色块作为预设预览，不生成真实预览图。

**理由**：
1. 生成真实预览图需要一张基准照片 + 14 种处理，文件体积大
2. 色块能传达"色彩风格"，用户能区分"暖调"和"冷调"
3. 实现简单，不依赖外部资源
4. 后续可以替换为真实预览图，架构不变

### 4.2 为什么预设放在最顶部？

**决策**：预设面板在右侧面板最顶部，默认展开。

**理由**：
1. 预设是最常用的入口，用户 80% 的修图从套预设开始
2. 像素蛋糕等竞品都把预设放在最显眼的位置
3. 默认展开让用户不用额外点击就能看到预设

### 4.3 为什么用分类 tab 而不是折叠列表？

**决策**：使用分类 tab（全部/婚纱/写真/...）而不是像素蛋糕的折叠列表。

**理由**：
1. 我们的预设数量少（14 个），折叠列表太复杂
2. Tab 更直观，用户一眼能分清类别
3. 实现简单，不需要折叠/展开逻辑
4. 后续预设多了可以再加折叠

### 4.4 为什么不引入图标库？

**决策**：使用 Unicode 字符作为 section 图标，不引入 Font Awesome 等图标库。

**理由**：
1. 减少依赖，保持轻量
2. Unicode 字符在所有浏览器/系统上都能显示
3. 颜色由 CSS 控制，和主题一致
4. 后续需要更精致的图标可以替换为 SVG

## 8. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 预设参数不均衡 | 某些预设效果不明显 | 调预设值时确保对比度足够 |
| 色块不能代表真实效果 | 用户预期不符 | 后续替换为真实预览图 |
| 面板变长 | 用户滚动操作增加 | 预设面板可折叠，其他 section 默认收起 |
| 窄屏体验差 | 手机用户看不到预设 | 窄屏时预设面板改为弹窗 |
