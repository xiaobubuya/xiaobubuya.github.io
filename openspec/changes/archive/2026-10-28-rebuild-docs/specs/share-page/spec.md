## Purpose

提供只读分享页：把一本相册以链接形式发给未登录的亲友查看，复用同一个 `reader.js` 阅读器渲染。分享页自身渲染静态结构，最终每本相册的专有预览（og 标签）由后端服务端渲染（不在本仓库）。

## ADDED Requirements

### Requirement: 只读分享页本体
系统 SHALL 提供 `share.html` + `share.js` 构成的静态只读分享页，凭链接 token 展示指定相册的阅读器视图（复用 `reader.js`），供未登录者翻阅，不提供编辑能力。该页面启动时以 `window.AlbumNavPage = { mode: 'brand' }` 声明，只显示品牌位、不显示三个 tab。

#### Scenario: 未登录凭链接翻阅
WHEN 未登录用户打开一个分享链接
THEN 页面只读渲染对应相册的逐页阅读器，可直接翻阅，但看不到也无法进入编辑功能。

#### Scenario: 品牌模式导航
WHEN 分享页启动
THEN 导航层只渲染品牌区，不渲染「照片 / 相册 / 修图」tab，避免误导未登录的亲友。

### Requirement: 专有预览由后端渲染
首页分享预览只能放通用兜底图（`og-cover.png`，且 `og:image` 必须是绝对 URL）；每本相册自己的 og 标签（标题/描述/封面）在分享链接被访问时由后端服务端渲染，本前端仓库 SHALL NOT 试图用纯前端 JS 生成每相册独特预览（微信爬虫不执行 JS）。

#### Scenario: 转发链接带相册自己的预览
WHEN 用户在微信里转发一条相册分享链接
THEN 卡片预览中的标题/描述/图片是那本相册的专有内容（由后端服务端渲染提供），而不是一行秃链接。
